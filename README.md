# 播浪

中文名：**播浪** · 前缀 `livewave` · 端口 **6400 / 11400**

## 骨架

**互动事件入流 → 事件时间水位线推进 → 热度窗关闭发射 → 迟到修正/撤回 → 窗输出与撤回互证**

皮：直播间点赞/送礼互动。去皮是事件时间窗计算 + 允许迟到与撤回，不是直播运营后台 CRUD，不是点击会话空闲切开。

## 冒烟

```bash
docker compose up -d --build
# http://127.0.0.1:6400
# 入流 → 灌「准时热度样例」→ 水位线/热度窗 → 再灌「迟到修正样例」看撤回 → 贯验
# 并发演练：事件流页「独立关窗扫描」与入流抢同房串行票；「关窗并发」页看冲突/命运/valid
```

## 关窗并发（架构甲：冲突整票回滚）

同房入流与关窗扫描抢同一张**房间串行票**，一房间一票、一票一事务，关闭态、窗合计、
水位、事件命运同票提交，禁止半截：

- 抢票失败 / SQLite 写保留冲突 / 窗行乐观版本过期 → 整票 `ROLLBACK` 到冲突前：
  本批事件不入互动事件、不抬水位、不动窗态，仅在独立台账库 `关窗并发账` 留**无效票**，可整票重试。
- 无冲突 → 整票提交。进程内同房互斥、异房并行；多进程部署置
  `并发.扫描立即写保留=True` 让扫描票预占写保留，跨进程冲突同样整票回滚。
- 两架构口径可区分：本架构（甲）冲突票事件**确定不入窗**；架构乙（乐观版本重试至入窗）未采用。
- 只读接口 `GET /api/并发关窗`：房间、冲突次数、事件命运、关闭态、valid；
  `GET /api/并发关窗/台账` 看票历；`POST /api/关窗扫描` 为独立准时关窗扫描入口。
- 夹具：`并发冲突甲样例`（冲突批，可整票不入）、`并发重试乙样例`（重试批，须入窗或合法旁路）。
- 测试：`backend/tests/`（8 项进程内并发 + 1 项跨进程 + HTTP 冒烟）。

## 入流命运账（命运码硬路由）

冲突处置**成功**必须把本票每个事件的命运与房间串行票**同票**写入 `入流命运账`：
房间键、事件编号、冲突世代、命运码、账号。后续重推与旁路一律先吃命运码，
不再凭「窗合计里有没有贡献」猜事件是否落地。

| 命运码 | 含义 | 重推处置（硬路由） |
| --- | --- | --- |
| `未入` | 确定未落窗（冲突整票回滚等） | 当**全新入流**走完整入流路径 |
| `已入` | 已落窗（含迟到修正撤回） | **幂等跳过**，不得再抬水位/改合计/双加 |
| `旁路` | 只经旁路入口落地 | **只许走旁路入口**，绝不再入窗 |

- 冲突整票回滚后补记 `未入` 并抬该房**冲突世代**；重试成功转 `已入`，账单调推进。
- 硬约束（`贯验` 与核证接口互证）：禁止冲突处置成功命运账空；禁止 `未入` 却窗内仍有
  该事件贡献；禁止 `已入` 却事件既不在窗也不在旁路。
- 只读核证：`GET /api/核证/入流命运?事件编号=&房间键=`（别名 `GET /api/入流命运核证`），
  返回命运账、硬路由标记、三禁止自检与 valid；`GET /api/并发关窗` 另含 `命运码现场`。
- 测试：`backend/tests/test_入流命运账.py`（10 项：甲乙夹具、旁路码、三禁止、并发不分叉）。

## 主链对象

| 对象 | 作用 |
| --- | --- |
| 互动事件 | 带事件时/处理时的点赞送礼 |
| 水位线 | 每房事件时水位 + 允许迟到秒 |
| 热度窗 | 翻滚窗；开启累计，关闭发射 |
| 撤回单 | 已关闭窗被允许迟到事件修正 |
| 旁路匣 | 超允许迟到 |
| 窗贯验 | 窗合计 ↔ 事件合计 ↔ 末次撤回 |
